# 설계 문서 — 넘패드 익숙해지기

> 1단계 산출물 · 작성일 2026-10-01 · 근거: [requirements.md](requirements.md)

## 1. 설계 원칙

1. **본분 우선**: 모든 화면은 "넘패드를 보지 않고, 빠르고 정확하게"라는 목표에 기여해야 한다.
2. **키보드만으로 조작**: 연습 중에는 마우스가 필요 없어야 한다. 홈과 결과 화면도 넘패드 키로 이동할 수 있다.
3. **즉각적인 피드백이 재미**: 누를 때마다 화면 키가 눌리고, 소리가 나고, 콤보가 오른다.
4. **순수 로직과 화면 분리**: 판정, 통계, 문제 생성은 DOM 없는 순수 함수로 두어 Node에서 테스트한다.

## 2. 연습 모드

| 모드 | ID | 제시 | 입력 판정 | 기본 세션 |
|---|---|---|---|---|
| 키 위치 익히기 | `keys` | 화면 넘패드에서 목표 키 하나를 강조 | 키 한 번 = 한 문항. 틀리면 그 자리에 머묾 | 30타 |
| 숫자 입력 | `number` | `38450`, `12.75` 같은 숫자열 | 글자마다 순서대로 판정(엄격 모드), 마지막에 `Enter` | 10문항 |
| 수식 입력 | `expr` | `1250*0.15+320` 같은 수식 | 숫자열과 같은 방식. 연산자 키 포함 | 8문항 |
| 빠른 계산 | `calc` | `37 + 48` 같은 사칙연산 문제 | 답을 자유롭게 입력(`Backspace` 허용) 후 `Enter`로 제출 | 60초 |

- **세션 길이**: 모든 모드에서 "문항 수"와 "타임어택 60초" 중 고를 수 있다(F10). 세션 엔진은 두 종료 조건을 모두 지원한다.
- **엄격 모드(keys, number, expr)**: 기대한 키가 아니면 오타로 기록하고 커서는 제자리에 둔다. 한 글자씩 판정하므로 "어느 키를 자주 틀리는지"를 정확히 셀 수 있다.
- **레벨(키 위치 모드)**: L1 `4 5 6` → L2 `7 8 9 1 2 3` 추가 → L3 `0 .` 추가 → L4 `/ * - + Enter` 추가. "전체"는 모든 키.
- **난이도(숫자, 수식, 계산)**: 쉬움, 보통, 어려움. 자릿수, 소수점 비율, 연산자 수로 조절한다.

## 4. 입력 판정 모델

`KeyboardEvent.code`를 **토큰**으로 정규화한다. `key`가 아니라 `code`를 쓰는 이유는 상단 숫자키(`Digit5`)와 넘패드(`Numpad5`)를 구분하기 위해서다.

| code | 토큰 |
|---|---|
| `Numpad0`~`Numpad9` | `0`~`9` |
| `NumpadDecimal` | `.` |
| `NumpadAdd` `NumpadSubtract` `NumpadMultiply` `NumpadDivide` | `+` `-` `*` `/` |
| `NumpadEnter` | `Enter` |
| `Backspace` | `Back` |

경고 판정:
- **넘패드 아님**: `Digit0`~`9`, `Period`, 메인 `Enter` 등 → `{ kind: 'notNumpad' }`. 오타로 세지 않고 경고만 한다.
- **NumLock 꺼짐**: `code`가 `Numpad숫자`인데 `key`가 숫자가 아님(`Home`, `ArrowUp` 등) → `{ kind: 'numLockOff' }`.
- `event.repeat`(길게 누름)는 무시한다.

## 5. 지표 정의

| 지표 | 정의 |
|---|---|
| 정확도 | 올바른 키 입력 수 ÷ 전체 판정 키 입력 수 |
| 속도(타/분, KPM) | 올바른 키 입력 수 ÷ 경과 분 |
| 콤보 | 연속으로 맞힌 키 수. 오타가 나면 0으로 초기화 |
| 약한 키 | 기대 키별 (오타 수 ÷ 시도 수). 히트맵의 색 농도 |
| 빠른 계산 전용 | 정답 수, 문항당 평균 시간. 정확도 = 정답 문항 ÷ 제출 문항 |

## 6. 데이터 저장

localStorage 키 `numpad.v1` 하나에 JSON으로 저장한다.

```js
{
  version: 1,
  settings: { sound: true, theme: 'auto', showKeypad: true },
  sessions: [ // 최신이 뒤. 최대 500개 유지
    { id, mode, level, date, durationMs, correct, total, kpm, accuracy, maxCombo,
      misses: { '7': 2, '.': 1 }, attempts: { '7': 10, ... } }
  ]
}
```
- 최고 기록은 저장하지 않고 `sessions`에서 계산한다(데이터 중복 방지).
- 읽기와 쓰기는 `try/catch`로 감싸, 저장소가 막힌 환경에서도 연습은 동작하게 한다.

## 7. 모듈 구조

```
index.html
css/
  tokens.css       디자인 토큰(색, 간격, 폰트, 라이트/다크)
  base.css         리셋, 타이포그래피, 레이아웃
  components.css   버튼, 카드, 키캡, 배지
  screens.css      화면별 스타일
js/
  main.js          앱 시작, 해시 라우터
  core/
    keys.js        넘패드 키 정의(토큰, 라벨, 격자 위치, 레벨)
    input.js       KeyboardEvent → 토큰/경고 정규화 (순수 함수)
    generator.js   문제 생성 (시드 가능한 난수, 순수 함수)
    session.js     세션 상태 기계: 판정, 콤보, 종료 조건 (순수)
    stats.js       지표 계산, 최고 기록, 약한 키 (순수 함수)
    storage.js     localStorage 읽기/쓰기, 마이그레이션
    sound.js       Web Audio 효과음(파일 없음)
  ui/
    dom.js         요소 생성 헬퍼
    keypad.js      화면 넘패드 렌더링, 강조, 히트맵
    chart.js       SVG 선 그래프
    confetti.js    최고 기록 축하 효과(canvas)
  screens/
    home.js  play.js  result.js  history.js
tests/
  unit/*.test.mjs  Node 내장 테스트 러너로 순수 모듈 검증
  e2e/             헤드리스 Chrome(DevTools 프로토콜)으로 실제 키 입력 검증
```

모듈 책임 요약: `core`는 DOM을 모르고, `ui`는 게임 규칙을 모르며, `screens`가 둘을 연결한다.

## 8. 디자인 방향

- **콘셉트**: "Numpad Dojo". 차분한 도장 같은 배경 위에 입체감 있는 키캡
- **색**: 중립 배경, 강조색 한 가지(인디고 계열), 정답은 초록, 오타는 코랄. 다크 모드 기본 지원
- **폰트**: 숫자는 고정폭 `JetBrains Mono`, 한글은 `Pretendard`. 로드 실패 시 시스템 폰트로 대체
- **움직임**: 키 누름(눌림 그림자), 콤보 팝, 오타 흔들림. `prefers-reduced-motion`이면 최소화
- **접근성**: 정답/오타를 색만이 아니라 아이콘(✓/✕)과 흔들림으로도 표시, 포커스 링 유지
